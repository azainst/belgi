# Цифровой мониторинг земель — MVP

Два модуля в одном сервисе (FastAPI + SQLite + aiogram 3):

1. **Веб-панель инспектора** — карта Leaflet (схема / спутник), цвета участков, карточка с фото, дедлайном и жизненным циклом.
2. **Telegram-бот для жителей** — статус заявления по трек-номеру, база знаний, «Народный контроль» (геопозиция → фото → описание).

## Запуск на Windows

1. Нужен Python 3. Проверка: откройте Пуск → впишите `cmd` → в открывшемся окне выполните `py --version`.
   Если пишет "не является внутренней или внешней командой", установите Python с
   https://www.python.org/downloads/windows/ — **на первом экране установщика обязательно
   поставьте галочку "Add python.exe to PATH"**, иначе ничего не найдётся.
2. Распакуйте архив (правой кнопкой по .zip → «Извлечь всё»).
3. Дважды кликните **`start.bat`** внутри папки `landmonitor`.

Скрипт сам создаст окружение, поставит зависимости, запустит сервер и откроет браузер на
http://127.0.0.1:8000, как только сервер будет готов отвечать — без гадания по таймеру.
Первый запуск занимает 1–2 минуты, дальше быстрее.

Для бота откройте `.env` (Блокнотом; если его нет — скопируйте `.env.example` и переименуйте
в `.env`) и впишите токен после `BOT_TOKEN=`, затем запустите `start.bat` заново.

Остановить сервер: закройте чёрное окно консоли или нажмите в нём Ctrl+C.

**Если двойной клик по `start.bat` или командой `py`/`python` неожиданно открывает Microsoft
Store** вместо запуска — это системная заглушка Windows. Отключите её: Параметры → Приложения →
Дополнительные параметры приложений → Псевдонимы выполнения приложений → выключите оба пункта
`python.exe`/`python3.exe`, затем установите Python с python.org, как в шаге 1.

## Запуск на Mac

1. Нужен Python 3 (проверка: в Терминале `python3 --version`; если нет, установите с python.org/downloads/macos).
2. Распакуйте архив. Откройте Терминал, впишите `cd ` (с пробелом), перетащите в окно папку `landmonitor` и нажмите Enter.
3. Выполните `bash start.command`. Скрипт сам создаст окружение, поставит зависимости, запустит сервер и откроет браузер.
4. Для бота откройте `.env` (скопируйте из `.env.example`; в Finder скрытые файлы показываются по Cmd+Shift+.) и впишите токен после `BOT_TOKEN=`, затем перезапустите.

Остановить сервер: Ctrl+C в окне Терминала.

## Запуск (общий вариант)

```bash
pip install -r requirements.txt
cp .env.example .env        # впишите BOT_TOKEN от @BotFather
python run.py
```

Откройте http://localhost:8000 (на Mac проще всего запускать через `start.command`, см. ниже). Публичный адрес и вебхуки не нужны: бот работает через long polling, а Telegram-бот подключается к серверу сам.

Без `BOT_TOKEN` запустится только веб-панель. Кнопка «Тестовый сигнал» в шапке имитирует сигнал жителя.

## Что добавлено в одиннадцатой версии

* **Запуск на Windows одним кликом.** Появился `start.bat` (плюс вспомогательный `wait_and_open.bat`): создаёт окружение, ставит зависимости, дожидается, пока сервер реально ответит, и только тогда открывает браузер на `127.0.0.1:8000` — по той же схеме, что и на Mac. Кириллица в окне консоли не превращается в «кракозябры» (`chcp 65001`, `PYTHONUTF8=1`).

## Что добавлено в десятой версии (важное исправление)

* **Отделённая точка была не видна, если оказывалась внутри настоящего участка.** Если обращение совпадает не с «пустым местом» (тогда работает кластеризация из прошлой версии), а с реальным кадастровым участком — несколько обращений просто добавляются к этому участку, это одна и та же земля, так и должно быть. Но если потом одно из них отделить, новая точка ставится на реальных координатах ЭТОГО обращения, а они, как правило, физически внутри того же участка. Раньше такая точка была тонким полупрозрачным кружком того же цвета, что и участок под ней, и терялась из виду. Теперь точки-обращения рисуются иначе: сплошная заливка, чёткая белая (или тёмная, если выбрана) обводка и тень — видно в любом случае, что под ним ни было. Нажатие по-прежнему открывает именно эту точку, а не участок под ней — это проверено, и раньше тоже работало правильно, просто было незаметно.

## Что добавлено в девятой версии

* **Фото у обращения стало необязательным.** На шаге «фото» можно нажать «⏭ Пропустить». Если фото так и не приложено, следующий шаг — описание словами — становится обязательным: пропустить его тоже нельзя, бот попросит написать, что произошло. Если хотя бы одно фото есть, описание по-прежнему можно пропускать, как раньше.
* **Пометка «без фото» у инспектора.** В очереди проверок и в списке при клике на объединённую точку (кластер) обращения без единого фото помечены отдельно — сразу видно, что подтверждения нет.

## Что добавлено в восьмой версии

* **Подпись на фото.** Раньше в карточке участка было не разобрать, какое фото относится к какому обращению. Теперь на каждой миниатюре — номер обращения (NK-00003, NK-00004…), а не общее «житель» / «инспектор».
* **Кластеризация точек на карте.** Если несколько точек на экране визуально сливаются (например, «отделили» обращение, а оно оказалось совсем рядом со старым), они показываются одним кружком с цифрой — сколько обращений внутри. По клику открывается список: номер, статус, цвет. Выбор любого пункта открывает его карточку и приближает карту — на увеличенном масштабе точки расходятся и показываются уже по отдельности. Если обращение одно — кружок обычный, без цифры, как раньше.

## Что добавлено в седьмой версии

* **Исправлен запуск на Mac.** Раньше `start.command` открывал браузер через фиксированную паузу в 2 секунды и по адресу `localhost` — если сервер не успевал стартовать (например, при первом запуске) или Safari не мог разрешить `localhost`, появлялась ошибка «сервер недоступен». Теперь скрипт реально дожидается ответа сервера (проверяет `/healthz`) и открывает `127.0.0.1:8000` — тот адрес, который у вас точно работал.

## Что добавлено в шестой версии

* **«Мои обращения» стали интерактивными.** Раньше это был просто список текстом. Теперь каждое обращение — кнопка; при нажатии бот присылает точку на карте (геолокацию) и все прикреплённые к этому обращению фото, затем карточку со статусом. Доступ проверяется: чужие обращения открыть нельзя, даже зная номер.

## Что добавлено в пятой версии

* **Радиус склейки увеличен до 150 м** (было 40), настраивается через `.env` (`SIGNAL_MERGE_RADIUS_M`, разумно 100–200).
* **Разделение обращений.** Если в радиус попали два разных нарушения, в карточке участка у каждого обращения (NK-...) есть кнопка «✂ отделить». Она выносит это обращение вместе с его фото в новую отдельную точку на карте, а уведомление о статусе уходит уже только тому, кто его отправил. Кнопка не показывается, если обращение в точке одно — отделять нечего.
* Отметка статуса всей точки, как и раньше, уходит сразу всем, кто в неё попал — это не изменилось, просто теперь можно заранее развести те обращения, которые попали в один радиус, но относятся к разным нарушениям.

## Что добавлено в четвёртой версии (исправления по вашим тестам)

* **Гонка при одновременных сигналах.** Если несколько человек отправляют сигнал из одной точки почти в одну секунду, теперь они гарантированно склеиваются в одну точку на карте, а не создают несколько разных. Раньше при редком, но реальном совпадении по времени это было возможно.
* **Несколько фото в одном обращении.** Бот теперь принимает подряд сколько угодно фото (в том числе присланные разом альбомом) и ждёт кнопку «✅ Готово», прежде чем перейти к описанию. Раньше сохранялось только первое фото, остальные терялись.
  Из-за этого у обычного обращения с одним фото добавился один лишний тап — нажать «Готово». Если хотите вернуть автоматический переход после первого фото и отдельно решать вопрос с альбомами позже, скажите, я подправлю.

## Что добавлено в третьей версии

* **Номер обращения (NK-00001, NK-00002…).** Каждое сообщение через «Сообщить о нарушении» получает свой номер. Житель может позже проверить статус по этому номеру через кнопку «Проверить статус заявления» — она понимает оба формата: трек-номер акимата (`KZ-2026-042`) и номер обращения (`NK-00001`). Инспектор видит те же номера в карточке участка.
* **Более понятные кнопки бота**, сформулированные как действия: «Проверить статус заявления», «Пошаговые инструкции», «Сообщить о нарушении», «Мои обращения», «Сменить язык».

## Что добавлено во второй версии

* **Мгновенное обновление** панели (SSE): точка появляется меньше чем за секунду.
* **Бот на русском и казахском**, кнопка смены языка, «Мои сигналы» со статусами. Казахские тексты стоит показать носителю языка.
* **Склейка дублей:** сигналы ближе 40 м друг от друга попадают в одну точку (счётчик обращений растёт).
* **Поиск** по кадастровому номеру, **аналитика** (просрочки, среднее время устранения, нарушения по видам).
* **Акт осмотра** одним нажатием (печать / сохранение в PDF).
* **Слой «Спутниковый анализ»** — демо-модель на тестовых данных, показывает идею масштабирования и умеет создавать проверки автоматически. Это не реальный анализ снимков.
* **Демо-фото** у тестовых нарушений (схематичные картинки с подписью «демо-изображение»).
* **Пароль инспектора** (`INSPECTOR_PASSWORD` в `.env`), Dockerfile, порт из переменной `PORT`.

Если у вас база от прошлой версии, она откроется сама, а кнопка «Сбросить демо» добавит демо-фото и показатели.

## Публикация в интернет (чтобы жюри писало боту само)

Бот сам подключается к Telegram, поэтому публичный адрес нужен только для веб-панели.

* **Быстро, с вашего компьютера:** `cloudflared tunnel --url http://localhost:8000` (или `ngrok http 8000`) выдаёт публичную ссылку. Подходит для демо, пока компьютер включён.
* **Постоянно:** любой хостинг, умеющий Docker (Render, Railway, Fly.io). Укажите переменные `BOT_TOKEN` и `INSPECTOR_PASSWORD`. Диск на бесплатных тарифах временный: данные вернутся к тестовым при перезапуске.
* Не запускайте одного и того же бота одновременно в двух местах.

## Замкнутый цикл (сценарий демо)

1. Житель: **📍 Народный контроль** → геопозиция → фото → описание.
2. На карте инспектора в течение ~4 секунд появляется всплывающее уведомление, участок (или новая точка) становится **жёлтым**.
3. Инспектор открывает карточку, выбирает «Выявлено нарушение», вид и срок → участок **красный**, житель получает уведомление в Telegram.
4. Дальше «В процессе устранения» → «Устранено / возвращено государству» (участок зелёный).

Если точка внутри известного участка, он становится жёлтым и получает фото и историю. Если вне, создаётся новая точка «на проверку».

## Данные

* Участки: `data/parcels.geojson` (14 фиктивных вокруг Тараза; пересоздать: `python tools/generate_test_geojson.py`).
* Свой GeoJSON организаторов: `python -m app.seed --reset --geojson путь/к/файлу.geojson`.
  Поля определяются автоматически (`cadastral_number`/`cadastral`/`number`…, `purpose`/`target_use`…, `area`/`area_ha`).
  Если площади нет, она считается по геометрии. Поддерживаются Polygon, MultiPolygon, Point.
* Тестовые трек-номера: `KZ-2026-042` (на рассмотрении), `KZ-2026-017` (выезд инспектора), `KZ-2026-008` (одобрено), `KZ-2026-055` (отказ), `KZ-2026-101`. Замените на выданные организаторами в `app/seed.py` (список `APPLICATIONS`).
* Сброс демо: кнопка «Сбросить демо» в шапке или `python -m app.seed --reset`.

> Тексты инструкций в боте (`KNOWLEDGE` в `app/bot.py`) демонстрационные. Сроки и перечни документов сверьте с актуальным законодательством.

## Структура

```
run.py                  запуск
app/main.py             API + запуск бота в одном процессе
app/services.py         логика: геопривязка, сигналы, статусы, аналитика, акт
app/i18n.py             тексты бота (ru / kk)
app/bot.py              Telegram-бот
app/seed.py             загрузка GeoJSON и тестовых обращений
app/static/index.html   веб-панель
start.bat / wait_and_open.bat   запуск на Windows (см. "Запуск на Windows" выше)
start.command                   запуск на Mac
data/                   БД SQLite, uploads/, parcels.geojson
```

## API

`GET /api/parcels` (GeoJSON) · `GET /api/parcels/{id}` · `POST /api/parcels/{id}/status` · `POST /api/parcels/{id}/photos` · `GET /api/parcels/{id}/act` · `GET /api/stats` · `GET /api/stream` (SSE)

## Что ещё продумано, но не реализовано

* **Срок хранения данных.** Если по обращению не подтвердилось нарушение (статусы «Нарушения нет» / «Устранено»), точку на карте, фото и связанные обращения имеет смысл хранить ещё какой-то срок (например, для истории и статистики), а затем удалять автоматически. Сейчас данные хранятся бессрочно, до ручного «Сбросить демо». Сам срок хранения (сколько дней/месяцев) нужно решить отдельно, вероятно, с оглядкой на требования к персональным данным. Автоматическое удаление пока не реализовано.

## Что сказать про масштабирование

* Интеграция с кадастровыми системами вместо GeoJSON (тот же формат Feature → замена источника в `seed.py`).
* Спутниковый мониторинг (Sentinel-2: NDVI) для автоматического выявления неиспользуемых участков и создания сигналов.
* Авторизация инспекторов (eGov/ЭЦП), роли и районы, PostgreSQL/PostGIS вместо SQLite, WhatsApp и eGov-каналы для жителей.
